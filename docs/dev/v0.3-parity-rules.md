# Rules for the v0.3 parity work (read before editing)

Goal: every screen keeps the layout, controls and behaviour of the founder's reference
screenshots, in the LeadCommons brand (dark theme, orange accent, tokens in
`static/css/app.css`) and in our own words.

1. **Own words.** Never copy a sentence from the reference screenshots. Short generic labels
   ("Save", "Export", "Location", "Job titles") are fine. Headings, help text, placeholders,
   empty states and tooltips are written fresh.
2. **Every control works, or says why not.** A control that cannot work here is visible,
   `aria-disabled="true"`, and has a tooltip (`title` or `data-tip`) saying why and how to turn it on.
   No dead buttons, no fake data, no fake numbers.
3. **Free and local-first.** There are no credits, plans or upsells. Where the reference shows
   credits or an upgrade, show something useful instead (a count, a time estimate, a link to
   the docs) or leave it out.
4. **Public, lawful data only.** Company data comes from the open packs (Wikidata, GLEIF,
   SIRENE). People and emails come from public web pages the user asks us to read.
5. **Demo mode** (the public Vercel site): enrichment, sending and LLM features are off.
   Their controls stay visible, disabled with the demo reason (`settings.enrichment_enabled`,
   `DEMO_DISABLED` in `web/jobs.py`).
6. **LLM features** need `LEADCOMMONS_LLM_URL` + `LEADCOMMONS_LLM_MODEL`. Without them, show
   the control disabled with that hint (see `ai_menu` in `templates/_search_macros.html`).
7. **Shared tree.** Several agents edit the repo at the same time. Edit only the files you
   own. For a shared file (`web/pages.py`, `static/js/app.js`, `templates/base.html`), make small
   `Edit` calls, re-read before editing, never rewrite the whole file, never undo someone
   else's change. Do not run `git commit`, `checkout`, `stash`, `reset` or `clean`: the lead
   commits.
8. **Proof.** Add pytest tests for new routes and behaviour. Before you finish, run
   `.venv/bin/pytest -q -p no:warnings`, `.venv/bin/ruff check src tests tools` and
   `.venv/bin/ruff format src tests tools`, and compare a Playwright screenshot of your screen
   with the reference image.

## Running the app for screenshots

```bash
cp -r <scratchpad>/parity-home /tmp/lc-<you>          # seeded: fake people + a list
LEADCOMMONS_HOME=/tmp/lc-<you> .venv/bin/leadcommons serve --port <your port> &
```

Use a fresh home (empty dir) for empty states. Capture at 1440x900. `tools/ux_audit/parity.cjs`
shows how each reference state is reached. `tools/ux_audit/audit.cjs` clicks every control.
